# Matrix 准备策略 · UX/UI 方向，目标大二

## 当前定位

> 我是一名大一学生，正在学习 UX/UI 与交互设计。目前主要借助 AI 制作可操作原型，以海报工具练习用户流程、界面状态和反馈。寒假计划入门计算机网络，之后补齐真实试用、设计迭代与协作记录，争取大二加入 Matrix。

这是学习阶段定位。现有项目可以证明有可运行的原型，不能自动证明本人独立设计、编程、做过用户研究或团队协作。学院、专业、投入时间及个人联系方式尚需本人确认。

## 材料分工

| 材料 | 当前用途 | 还缺什么 |
| --- | --- | --- |
| 个人作品集网站 | 汇总原型、设计分析与学习进度 | 真实个人信息和持续更新的个人实践 |
| Poster Lab | 主案例：文字编辑、预览、撤销、草稿、导入导出 | 本人画的线框稿、试用记录、方案选择与复测 |
| Wayfinder | 键盘交互、空态与权限反馈 | 实际可用性观察与改进依据 |
| Margin / Cutroom | 即时预览与状态同步练习 | 选择一个深化，避免每个只讲技术名词 |
| 网络入门笔记 | 对加载、请求、错误与恢复的理解 | 寒假完成的实验、截图与状态图 |

网站三组设计分析是 AI 辅助案头分析；用户可能误解是待验证假设，不是已发生的投诉。方案 B 是比较草案，不代表已经改善可用性或部署到工具。

## 优先补齐的个人证据

1. 本人走完海报流程，画出所见状态；能解释 PNG、JSON、本机草稿和撤销历史的区别。
2. 针对一个任务制作两版线框稿，说明为何保留或舍弃某个入口。
3. 邀请自愿试用的同学完成任务，记录原话、操作与停顿。征得同意才录制，公开案例时去除个人信息。
4. 根据观察修改一个点，再用相同任务复测。没有改善也可以记录原因，不预填完成率或提升百分比。
5. 完成一次真实协作或交付练习，留下组件状态、沟通与修改记录。

## 正式投递前

核对届时 Matrix 官方招新信息，包括方向、年级范围、材料和联系方式。当前以 UX/UI 为兴趣方向，不将过去的开发要求改写成官方设计岗规则，不承诺入选。

建议材料：一页学习经历摘要、作品集链接、两份完整设计案例、可操作原型、真实贡献与投入时间。主讲海报案例，其他项目作为补充。

AI 使用说明可以是：

> 这些原型主要借助 AI 完成。它们是我的学习素材；我正在逐步独立完成任务梳理、线框稿和试用。已经由我完成的部分是……，对应材料是……；尚未完成的部分仍标为计划。

省略号由实际经历填写。不要使用“AI 只写样板，我负责全部架构与调试”等未经核实的话术。

## 案例讲解

用具体任务串起背景、观察、方案、取舍与验证，再现场演示。技术问题讲本人能核对的流程，不把代码库存在某项能力等同于自己已熟练掌握。

当前全站 40 项单元测试，其中海报模型测试 6 项；这是工程验证，不是用户测试，也不证明本人会 Git 团队协作。展示案例时优先讲设计依据与真实实践。
