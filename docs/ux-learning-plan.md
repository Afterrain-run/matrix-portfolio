# 12 周学习计划 · UX/UI 基础与设计案例

适用情况：大一，项目主要借助 AI 完成，希望学习 UX/UI，寒假入门计算机网络，争取大二加入 Matrix。以下是建议节奏，不是团队招新要求；从实际开始学习的那周起算，允许因课业延长。每周投入多少时间由本人决定，不预设时间承诺。

## 每周产物

每周保存一份可查看的产物和一段简短复盘：做了什么、依据是什么、AI 帮了什么、还有什么不懂。使用自己能上手的设计工具即可，先完成过程，不急着增加工具数量。

| 周次 | 重点 | 可以检查的产物 |
| --- | --- | --- |
| 1 | 梳理海报工具的实际功能 | 输入到导出的流程图，标明本机保存、JSON 和 PNG 的区别 |
| 2 | 视觉层级与信息组织 | 两版线框稿，说明标题、主操作、次操作为何这样排序 |
| 3 | 状态与反馈 | 正常、空输入、存储失败、导入失败、导出中等状态清单；标注已实现与缺失项 |
| 4 | 设计一个完整任务 | 选择下载图片或保留可编辑稿，画出入口到结果的低保真流程 |
| 5 | 比较方案 | 两个可点击方案；列出理解成本与恢复路径，不预写优胜结论 |
| 6 | 准备试用 | 招募自愿参与的同学，写任务、观察表与简短说明，不提前教其操作 |
| 7 | 开展探索性试用 | 尽量邀请 3–5 人，记录独立完成情况、停顿、误解和原话；样本有限，不外推所有用户 |
| 8 | 根据观察迭代 | 选一个有证据的问题，保存修改前后稿、取舍理由与复测记录 |
| 9 | 组件与视觉规范 | 按钮、表单、间距、文字层级及错误状态组件页，检查键盘焦点与文本可读性 |
| 10 | 移动端与交付 | 手机流程、长内容与异常状态说明，向同学解释一个交互并记录理解偏差 |
| 11 | 整理第一份案例 | 背景—任务—观察—方案—验证—迭代—限制，附实际材料，不填造访谈与指标 |
| 12 | 复盘与下一题 | 录案例讲解，列出本人能解释和修改的部分，为第二个真实问题拟研究计划 |

## 寒假网络入门：独立模块，按校历安排

不用等上述 12 周全部完成。寒假到来时可切换到以下四个模块，按假期长度调整。网络基础用于理解系统约束；海报工具目前在浏览器本地处理内容，没有上传接口，不能把本地保存说成网络请求。

| 模块 | 需要理解 | 小实验与设计产物 |
| --- | --- | --- |
| 地址与连接 | 域名、DNS、IP、端口、TCP 的基本作用 | 画出打开网页的大致过程；知道 Network 面板的观察范围，不把推测当作可见证据 |
| 请求与响应 | URL、方法、状态码、请求头、响应体、HTTPS 的保护范围 | 查看本作品集的文档、脚本、字体请求，记录资源加载顺序 |
| 等待与失败 | 慢网、离线、超时、错误响应；结果未知与明确失败不同 | 在独立练习原型中表达加载、空结果、失败和重试，说明重试可能导致重复提交 |
| 缓存与恢复 | 浏览器缓存与本地存储不同，刷新不保证所有资源重新下载 | 对比缓存开关下的请求，为刷新后继续编辑与网络中断分别画状态图 |

完成标准：用自己的话讲解一次请求，拿出可观察的截图与状态图。不会的内容明确标注，不以背术语或覆盖率数字作为掌握证明。

## 大一下学期、暑假与大二申请

- 深化海报案例，再选择一个本人接触过、允许观察的校园任务做第二份案例。先收集实际使用过程，再决定是否改版。
- 练习一次小范围协作：说明组件、状态、尺寸和反馈，保存沟通与交付记录。没有发生就写计划。
- 大二招新前核对当期方向、年级范围和申请方式；当前海报不能保证下一年要求不变，也不能保证有单独 UX/UI 岗位。
- 最终准备：两个能解释设计依据的案例、可操作原型、个人贡献说明、真实联系方式与可投入时间。
